# Implementation plan: hook-xray 0.1.0 (first public release)

**Scope:** presentation and source diagnostics only. No new hook-risk analysis; the "conversation event + network" mod rule stays in v0.2.

**Rule for every step:** `lint()` and the rules in `src/lint/rules.ts` don't change. The baseline test (step 0) proves it.

## Before you start (new session)

1. Read `CLAUDE.md` and `docs/context.md`. They hold the rules and the verified Claude Code behavior this plan relies on.
2. Check the baseline is green: `npm test` should pass (26 tests at the start of step 1).
3. Work through the steps in order. After each: `npm test`, `npm run typecheck`, update the Status table below, commit that step on its own. Never push; the maintainer pushes.
4. Tests were written on Linux. On Windows, expect path-related surprises; the Windows redaction bug in step 6 is the known one. Fix any others you find in the same step, with a test.
5. `mods/hook-xray-live/tsconfig.json` and `.claude-plugin/types/` are generated by Claude Code and already in `.gitignore`.
6. Keep README.md true at every commit: update it in the same commit as each step that changes behavior, and delete the matching "Known gap" note when you fix one.

## 1. Source status: missing / unreadable / invalid / found

`src/discover/fs.ts`
```ts
export type ReadStatus = "missing" | "unreadable" | "invalid";
export type JsonResult =
  | { ok: true; value: unknown }
  | { ok: false; missing: boolean; status: ReadStatus; error?: string };

// readJson: !existsSync → missing; readFileSync throws (EISDIR, EACCES, EPERM) → unreadable,
// error = e.code; JSON.parse throws → invalid, error = parse message.
```

`src/types.ts` (additive)
```ts
export type SourceStatus = "found" | ReadStatus;
interface ScannedSource { /* existing fields */ status: SourceStatus }
interface Inventory { /* existing */ parseErrors: { file: string; error: string; kind?: "unreadable" | "invalid" | "schema" }[] }
```

`src/discover/index.ts`: `note()` takes a `SourceStatus` and derives `found = status === "found"`. Every `readJson` call site passes `r.ok ? "found" : r.status`; directory checks (skills, agents, `managed-settings.d`, `dev-mods`) pass `found` or `missing`. `parseErrors` entries get `kind`. Hook-schema errors from `addHooks` get `kind: "schema"`.

## 2. Scratch-workspace labels

Claude desktop scratch folders (`…\Claude-Data\…\scratch-workspaces\…`) are temporary. Label them; never drop them from the scan.

`src/types.ts`: `Inventory.projectDetails: { path: string; scratch: boolean }[]` (additive; `projects: string[]` stays).

`src/discover/index.ts`
```ts
export const isScratch = (p: string) => /[\\/]scratch-workspaces[\\/]/i.test(p);
inv.projectDetails = inv.projects.map((path) => ({ path, scratch: isScratch(path) }));
```

`where()` in `src/lint/rules.ts` is presentation, so it may take an optional `scratch` flag and append ` (scratch)`. No rule reads it.

## 3. Finding groups

New `src/report/group.ts`, pure:
```ts
export interface NoteGroup {
  rule: string; message: string; fix?: string; why?: string;
  confidence: Confidence; hookIds: string[];
  owners: { label: string; count: number; plugin: boolean }[];   // "lint-kit ×2, deploy-tools ×1"
}
export interface Grouped {
  blocking: Finding[];    // NEVER_RUNS rules + double-run-copy, one per hook
  warnings: Finding[];    // other warning/attention hook findings, one per hook, never collapsed
  modFindings: Finding[];
  notes: NoteGroup[];     // info hook findings, keyed by rule + exact message
}
export function groupFindings(inv: Inventory, findings: Finding[]): Grouped;
```

Ordering: within each list, plugin owners after the user's own config, then by event. Notes sorted by number of affected hooks, descending.

## 4. Terminal layout + `--expand`

Rewrite `src/report/terminal.ts`. Default output, in order:

1. Header: `hook-xray 0.1.0 · read-only, nothing was executed`, then counts, e.g. `5 hooks · 3 plugins · 1 mod · 9 projects (1 scratch)`.
2. Global state lines (`disableAllHooks`, `allowManagedHooksOnly`, `allowedHttpHookUrls`): unchanged.
3. **Never runs or runs twice**: one block per finding: hook line (id, event, matcher, type, owner, timeout), command, message, fix.
4. **Warnings**: same block format, one per finding. Never collapsed.
5. **Mods**: always shown. No mods → `No mods found.` A mod with no findings still lists hooks, calls, env and state.
6. **Notes**: one line per `NoteGroup`: message, `N hooks: lint-kit ×2, deploy-tools ×1`, fix. With `--expand`, each affected hook on its own line underneath.
7. **Hooks by owner**: compact inventory, one line per hook, grouped by owner (your settings first, then each plugin).
8. **Could not read**: split into `unreadable` and `invalid` (and `schema`).
9. Sources footer (step 5).

Ownership wording:

| Finding | Plugin-owned remediation line |
|---|---|
| blocking or warning | `Plugin-owned: report it to the author; disable the plugin if the behavior is unwanted.` |
| info note, all owners plugins | `Plugin-owned: report it to the author.` |
| info note, mixed owners | `Plugin-owned ones: report them to the author.` |

Redaction: one helper `r(text)` used for **every** message, fix, command and path: `redactText(text, home)` plus project-path shortening (`…/<last folder>`) when `--redact` is set.

`src/cli.ts`: add `.option("--expand", "list every hook behind each collapsed note, and every missing source with --sources")`, pass it to `renderTerminal`. `--event` keeps filtering before grouping.

Summary lines from `summarize()` stay in JSON. The terminal shows them without the `  •` sub-bullets, which the sections now cover.

## 5. Short `--sources`

Default footer: `<found> of <total> sources present · --sources for details · --json for everything`.

With `--sources`:
- list `found`, `unreadable` and `invalid` entries only
- then summary lines:
  - `9 projects checked: 2 with .claude config, 7 without, 1 scratch workspace (temporary)`
  - `6 plugins: 4 with hooks, 2 without (normal)`
  - `managed settings: none found` / `found`
- `--sources --expand` also lists every missing path

## 6. Additive JSON

`src/report/json.ts`; nothing renamed or removed:
- `version` from `package.json`
- `sources[].status`
- `projectDetails` (paths shortened under `--redact`)
- `parseErrors[].kind`
- `groups`: `NoteGroup[]` with `hookIds` (messages redacted under `--redact`)

`--json` always carries every hook and every finding, whatever `--expand` says.

**Bug to fix here (Windows):** under `--redact`, project paths outside the home folder (e.g. `D:\Work\…`) leak in `sources[].path` and `parseErrors[].file`. `p()` only replaces the home folder, and the project-path replacement runs *after* `JSON.stringify`, where every `\` is already escaped to `\\`, so it never matches. Fix: shorten project paths in every string field before stringifying (one `redactPath()` used for sources, parse errors, hook files, mods and groups), and delete the post-stringify replacement.
